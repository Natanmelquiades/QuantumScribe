# STORY 2.2: Completar os comandos de diagnóstico e manifestos do CLI

## User Story

**Como** proprietário do QuantumScribe,
**quero** que os comandos anunciados pelo CLI AIOX funcionem desde uma instalação local limpa,
**para que** eu consiga diagnosticar a instalação e validar a integridade dos componentes sem depender de correções manuais ocultas.

## Contexto

Na auditoria ampliada da Story 2.1, o CLI local respondeu corretamente a `--help`, mas anunciou `doctor` sem registrar o comando. A validação de manifestos também falhou porque os três CSVs canônicos ainda não estavam disponíveis em `.aiox-core/manifests/`, apesar de existirem os geradores e validadores oficiais.

## Acceptance Criteria

1. O comando `node .aiox-core/cli/index.js doctor` está registrado, executa os checks existentes e retorna saída textual útil.
2. O comando `doctor` suporta as opções documentadas pelo módulo (`--json`, `--fix` e `--dry-run`) sem quebrar o processo de inicialização.
3. O `--help` do CLI anuncia somente comandos realmente registrados, incluindo `doctor` quando implementado.
4. `node .aiox-core/cli/index.js manifest regenerate --force` gera `agents.csv`, `workers.csv` e `tasks.csv` em `.aiox-core/manifests/`.
5. `node .aiox-core/cli/index.js manifest validate` passa após a regeneração e identifica com erro acionável um manifesto ausente ou inválido.
6. Os validadores AIOX, a sincronização Codex e os testes do QuantumScribe continuam passando.

## Dev Notes

- O módulo de diagnóstico existente é `.aiox-core/core/doctor/index.js` e expõe
  `runDoctorChecks(options)`, retornando `{ formatted, data }`.
- O gerador existente é `.aiox-core/core/manifest/manifest-generator.js`; o validador
  correspondente é `.aiox-core/core/manifest/manifest-validator.js`.
- Os comandos Commander seguem o padrão de `.aiox-core/cli/commands/metrics/index.js`
  e `.aiox-core/cli/commands/config/index.js`.
- O diretório canônico dos artefatos é `.aiox-core/manifests/`, conforme os módulos de
  geração e validação; não criar um segundo diretório `manifest/`.
- A correção deve ser incremental: registrar o módulo existente e gerar os artefatos
  canônicos, sem duplicar Doctor/Manifest ou substituir o framework inteiro.
