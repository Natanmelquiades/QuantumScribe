# STORY 2.3: Alinhar os limites de qualidade após a instalação do AIOX

**ID:** 2.3

**Status:** Done  
**Executor:** @dev  
**Quality gate:** @architect  

## User Story

**Como** responsável pela manutenção do QuantumScribe,  
**quero** que os gates do projeto distingam o código do produto das projeções e scripts do AIOX,  
**para que** uma instalação válida do framework não produza falsos erros de lint nem bloqueie o fluxo de entrega.

## Contexto

Após o commit isolado da instalação AIOX, o CLI e os validadores passaram, mas `ruff check .`
passou a inspecionar scripts Python distribuídos em `.aiox-core` e nas skills Claude. Esses
artefatos pertencem ao framework/projeções e não ao código Python do QuantumScribe; o limite
atual do `pyproject.toml` exclui apenas diretórios de build do produto.

## Acceptance Criteria

1. `ruff check .` verifica o código Python do QuantumScribe e passa sem analisar scripts
   distribuídos em `.aiox-core` ou projeções de skills/IDE AIOX.
2. `localwhisper/`, `main.py` e `tests/` permanecem dentro do escopo do Ruff e da regressão
   Python; nenhuma raiz do produto é excluída para mascarar defeitos.
3. `node .aiox-core/cli/index.js doctor --json`, os validadores AIOX e o registry continuam
   sem falhas após o ajuste de configuração.
4. `python -m compileall -q localwhisper main.py`, `python -m pytest -q` e `python -m pip check`
   passam no checkout limpo.
5. O ajuste é documentado no file list e não reabre nem altera o lifecycle da Story 2.2.

## Scope

- Ajuste da configuração Ruff para delimitar o framework e as projeções AIOX.
- Reexecução sequencial dos gates AIOX e Python no checkout limpo.
